# Craft & Find — Fabric 1.21.1

**Автор / namespace:** `overyourhead`  
**Java package:** `com.overyourhead.craftandfind`  
**Блок:** `Storage Workbench` / `Складской верстак`  
**Порт:** NeoForge → Fabric, Minecraft **1.21.1**

Порт сохраняет исходную структуру проекта, игровую логику и исходные ресурсы. Loader-specific части NeoForge заменены на Fabric API/ванильные реестры, а `assets/`, `data/`, mixin-конфиг, модели, текстуры и рецепты перенесены без изменения содержимого.

## Основной функционал

- приватная сетка крафта 3×3 для каждого игрока, измерения и конкретного Складского верстака;
- сохранение раскладки после закрытия GUI и повторного входа в мир;
- книга рецептов учитывает инвентарь, сетку крафта и ближайшие контейнеры;
- рецепт автоматически забирает материалы сначала из игрока, затем из хранилищ;
- ghost-рецепт для недоступного крафта;
- вкладка ближайшего хранилища, поиск, алфавитная сортировка и сортировка по количеству;
- ЛКМ по найденному предмету закрывает GUI и подсвечивает подходящие контейнеры;
- персональная подсветка, частицы, маркер предмета и звуки;
- серверная повторная проверка контейнеров и извлечения предметов;
- радиус ближайших хранилищ по умолчанию: **16 блоков**.

## Модульный GUI

Координаты GUI собраны в `WorkbenchLayout`, пути к изображениям — в `WorkbenchTextures`.
Карта ресурсов находится в:

```text
src/main/resources/assets/craftandfind/textures/gui/workbench/README.md
```

Обычный ресурспак, меняющий только `assets/minecraft`, не заменяет элементы Craft & Find. Для отдельной темы заменяйте ресурсы в `assets/craftandfind`.

## Конфиги

Клиентский конфиг создаётся в:

```text
config/craftandfind-client.toml
```

Серверный конфиг создаётся рядом, как в исходном dev-проекте NeoForge:

```text
config/craftandfind-server.toml
```

Диапазоны и значения по умолчанию сохранены из исходного мода.

## Сборка

Требуется **Java 21**.

В проекте сохранены скрипты для Gradle Wrapper. Если `gradle/wrapper/gradle-wrapper.jar` отсутствует, сначала запустите:

Windows:

```bat
setup-wrapper.bat
```

Linux/macOS:

```sh
./setup-wrapper.sh
```

Затем:

```bat
gradlew.bat runClient
gradlew.bat build
```

или:

```sh
./gradlew runClient
./gradlew build
```

Готовый JAR будет в `build/libs/`.

## Что проверить в игре

1. Открыть два разных Складских верстака и оставить в них разные раскладки.
2. Повторно открыть каждый блок и проверить восстановление именно его сетки.
3. Зайти вторым игроком и проверить независимую приватную сетку.
4. Нажать недоступный рецепт — должны появиться ghost-ингредиенты.
5. Нажать доступный рецепт — материалы должны подтянуться из ближайших контейнеров.
6. Проверить `Search...`, поиск и обе сортировки.
7. Положить больше 25 типов предметов и проверить прокрутку.
8. Нажать предмет в складской вкладке — GUI закроется, контейнеры подсветятся.
9. Перезапустить мир/сервер и проверить сохранение приватных раскладок.

## Ограничения исходного MVP

- Поддерживаются блок-сущности, реализующие ванильный `Container`.
- Специализированные инвентарные API сторонних модов не подключены; это соответствует исходному MVP, где NeoForge-only `IItemHandler` также ещё не поддерживался.
- Чёрный список отдельных сундуков не добавлен.
- Снимок ближайшего хранилища обновляется примерно раз в секунду при открытом GUI.
